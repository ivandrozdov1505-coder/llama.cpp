# Dory Workbench

Русскоязычное настольное приложение на Rust для локальной Dory и других GGUF, которые поддерживает этот форк llama.cpp.

## Запуск

Установи Rust 1.91 или новее. Для автоматической сборки движка также нужны CMake в PATH и C++-компилятор. На Windows подойдёт Visual Studio Build Tools с компонентом **Desktop development with C++**. Для режима CUDA дополнительно установи CUDA Toolkit и драйвер NVIDIA.

Из корня форка выполни:

```powershell
cargo run --release --locked --manifest-path apps/dory-workbench/Cargo.toml
```

1. Нажми **Выбрать GGUF** или перетащи существующий файл в окно.
2. Выбери **Авто**, **CUDA**, **CPU** или **Готовый сервер** во вкладке **Модель**.
3. Нажми **Запустить**. Приложение настроит сборку CMake, запустит движок и дождётся готовности модели. Для повторных запусков CMake использует предыдущую сборку.
4. Напиши сообщение в **Чате**. Остановка движка освобождает модель из памяти. При закрытии окна процесс сервера завершается.

Движок собирается из локального форка в `.engine-build/`. **Авто** выбирает CUDA при наличии GPU и `nvcc`. Если сборка CUDA не удалась, приложение показывает сообщение в журнале и собирает CPU-вариант. Для **Готового сервера** выбери `llama-server.exe` или `llama-server`, собранный из этого форка с нужным бэкендом. В Linux для диалога выбора файлов используется XDG Desktop Portal. Можно также перетащить GGUF в окно.

## Агент

В режиме **Агент** выбери папку проекта. Агент может просматривать каталог, читать строки файлов, предлагать создание или замену файлов, искать в DuckDuckGo и запускать PowerShell в папке проекта. Перед записью, поисковым запросом и запуском команды приложение показывает содержимое операции и запрашивает подтверждение. Команды выполняются с правами текущего пользователя. В Linux для них нужен `pwsh` в PATH. Для вызова инструментов нужна модель с подходящим шаблоном чата. Его можно заменить Jinja-файлом в настройках.

Включи **Показывать круги в реальном времени** перед запуском движка. В диагностическом режиме сервер сообщает о завершении рекуррентных проходов Dory из вычислительного графа. Диагностика добавляет синхронизацию и может снижать скорость. Круги Dory и текст рассуждения в ответе отображаются отдельно.

## Контекст

Workbench применяет шаблон чата и считает токены через тот же движок. При заполнении окна модель сворачивает старые сообщения и вывод инструментов в резюме. Полный журнал остаётся в диалоге. Резюме и число занятых токенов доступны через кнопку **Контекст**. Для сторонних клиентов у границ контекста работают механизмы самого клиента и сервера.

## OpenCode и другие клиенты

Во вкладке **API** включи доступ для клиентов и запусти модель. По умолчанию сервер слушает только локальный адрес. Для подключения с другого компьютера есть настройка локальной сети, использующая HTTP. Клиенту нужны адрес вида `http://127.0.0.1:8080/v1`, идентификатор `dory-local` и ключ. Все значения можно скопировать из приложения.

Для OpenCode скопируй конфигурацию подходящей версии и вставь в `opencode.json` проекта. Если файл уже существует, добавь провайдер в имеющийся JSON. Ключ привязан к настройкам Workbench, поэтому файл с ним лучше хранить локально.

[Настройка провайдеров OpenCode](https://opencode.ai/docs/providers/)

## Проверки

```powershell
cargo test --locked --manifest-path apps/dory-workbench/Cargo.toml
```

Для сквозной проверки нужен `llama-server` из этого форка и тестовый локальный Dory GGUF. Укажи абсолютные пути в переменных `DORY_TEST_SERVER` и `DORY_TEST_MODEL`, затем запусти тест `live_dory` с флагом `--ignored`.
